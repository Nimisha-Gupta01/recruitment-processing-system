Security — Only if Asked
1 min
JWT Authentication
Token genJwtUtil.generateToken(email, role, userId) — HMAC-SHA signed, 24hr expiry
StorageToken in httpOnly cookie — cannot be read by JavaScript — XSS-safe
FilterJwtAuthFilter intercepts every request — reads cookie "jwt" first, falls back to Authorization header
PrincipalSets SecurityContextHolder with UsernamePasswordAuthenticationToken(email, null, [ROLE_X])
Route Protection
FrontendProtectedRoute in App.jsx — reads role from localStorage, redirects wrong-role users
BackendSecurityConfig — hasRole('EMPLOYER') on employer endpoints, hasRole('CANDIDATE') on candidate endpoints
IDOR prev.Service layer checks ownership — employer cannot access another employer's applications
Why JWTStateless — no server-side session store, scales horizontally without sticky sessions

Likely Questions — 30-Second Answers
Why Spring Boot and not Node.js or Django?
Strong typing, built-in Spring Security, JPA ORM, production-ready starters, and Java 21 virtual threads for concurrency. Right choice for an enterprise data-heavy system where type safety matters.
Why MySQL and not PostgreSQL or MongoDB?
Recruitment data is highly relational — candidates, vacancies, applications, interviews all reference each other with foreign keys. ACID transactions matter. MySQL 8 handles all our query patterns well.
Why two-panel layout on Applications page instead of a table?
Tables force horizontal scrolling and can only show a few columns. Two-panel shows the full application detail — resume, cover note, AI summary, all actions — without leaving the page. Same pattern as Gmail, Jira, Outlook.
What does the AI actually do?
Sends the job description + candidate's cover note to an AI API, gets back a 1–100 score and plain-English summary. Both are stored on the applications table and shown in the blue callout. Fully automated — no manual scoring.
What prevents double-applying?
ApplicationService.apply() queries existsByVacancy_VacancyIdAndCandidate_CandidateIdAndStatusNot(vacancyId, candidateId, "Withdrawn") — throws an error if a non-withdrawn application already exists.
What is the 3-month re-apply cooldown?
After a candidate withdraws, withdrawnAt.plusMonths(3) is compared to now() in apply(). Prevents candidates from gaming the system by applying, withdrawing, and applying again to game the AI score.
Is the JWT stored in localStorage? Isn't that insecure?
No — the JWT token is in an httpOnly cookie, which JavaScript cannot read, making it XSS-safe. Only non-sensitive metadata (role, userId, name) is in localStorage. The JwtAuthFilter reads the cookie on every request.
How does the notification system work?
NotificationService.notify() always saves to the notifications table first, then attempts sendEmail() — which fails silently if no mail server is configured. In-app notifications always work; email is optional.
